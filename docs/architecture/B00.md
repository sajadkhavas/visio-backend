# B00 — Backend Foundation Architecture

## Purpose

B00 creates the smallest production-shaped Django foundation needed before VISIO commerce domains are implemented. It deliberately keeps domain behavior out of the foundation.

## Runtime baseline

- Python 3.13.15
- Django 5.2.17 LTS
- Django REST Framework 3.18.0
- PostgreSQL 16.15
- psycopg 3.3.5
- uv 0.12.9 with a committed lockfile

The runtime is a modular monolith. Redis, queues and distributed infrastructure are not introduced until a measured requirement exists.

## Settings boundary

`manage.py` defaults to local settings for developer ergonomics. ASGI/WSGI default to production settings so an accidentally deployed process fails closed when required production environment variables are missing.

Production requires a strong secret key, explicit allowed hosts and PostgreSQL credentials. HTTPS redirect, secure cookies and HSTS are enabled in the production settings module.

`SECURE_HSTS_INCLUDE_SUBDOMAINS` and `SECURE_HSTS_PRELOAD` intentionally remain disabled by default in B00. Django warns that HSTS directives must be enabled carefully, and `includeSubDomains` commits every subdomain to HTTPS. VISIO's final production domain/subdomain topology and preload policy belong to R00/S00, where DNS/TLS ownership can be proved. The permanent deployment-check script therefore fails on every deployment error or unexpected warning while explicitly allowing only `security.W005` and `security.W021` until that later gate. Once the production topology is frozen, those two deferrals must be removed or replaced by the final documented HSTS policy.

## Identity timing

`accounts.User` exists before the first accepted application migration. It intentionally inherits Django's `AbstractUser` without selecting the final login identifier in B00; authentication policy belongs to B01. This preserves a swappable project user model without prematurely deciding email/phone/OTP behavior.

## HTTP contracts

- public API prefix: `/api/v1/`
- OpenAPI schema: `/api/v1/schema/`
- process liveness: `/health/` (no database dependency)
- readiness: `/ready/` (PostgreSQL `SELECT 1`; 503 on failure)
- API exception semantics: RFC 9457-style Problem Details with `application/problem+json`

## Database contract

PostgreSQL is used in CI and production. SQLite is not an acceptance substitute. CI proves migration from zero and migration drift on the exact phase head.

## Quality contract

Permanent gates are frozen dependency installation, Ruff format/lint, mypy with django-stubs, Django system checks, pytest against PostgreSQL, migration drift, migrate-from-zero, OpenAPI generation, explicit production deployment-check review, immutable action pins and secret sanity.

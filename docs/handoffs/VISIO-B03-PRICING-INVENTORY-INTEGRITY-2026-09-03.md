## Accepted architecture

### Money

- price authority is backend-only;
- VariantPrice is one-to-one with B02 ProductVariant;
- exact storage uses `DecimalField(max_digits=18, decimal_places=0)`;
- canonical currency identity is `IRR`;
- catalog/storage/display operational unit is integer Toman;
- frontend display unit is `تومان`;
- no float is allowed for authoritative money;
- compare-at is null or strictly greater than current price;
- provider/payment conversion is B07 authority;
- final checkout repricing/totals are B05 authority;
- immutable order snapshots are B06 authority.

### Inventory

- VariantInventory is one-to-one with ProductVariant;
- `on_hand` is stored stock truth;
- no duplicated mutable `reserved` counter exists;
- active, unexpired InventoryReservation rows are hold truth;
- available-to-promise is derived;
- missing/inactive commerce truth fails closed.

### Reservations

- active / released / consumed / expired states;
- 15-minute default TTL;
- expired active rows do not reserve stock after expiry;
- authoritative mutation paths lazily normalize stale holds;
- release is idempotent for released/expired state;
- consume decrements stock once and only from an active unexpired hold;
- on-hand adjustment cannot cross below active reservations.

### Concurrency

- short explicit `transaction.atomic()` blocks;
- `select_for_update()` on authoritative inventory rows;
- inventory lock before reservation lock for transitions;
- deterministic ordering required for future multi-row operations;
- real PostgreSQL transaction/concurrency acceptance test remains mandatory.

## Public catalog boundary

B02 identity/presentation remains authoritative and unchanged. B03 enriches the existing product/variant contract with authoritative commerce projection only when B03 truth exists.

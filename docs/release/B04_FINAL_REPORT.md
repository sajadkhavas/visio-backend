## Delivered domain

B04 introduces the `apps.cart` Django application with:

- authenticated user-owned `Cart`;
- `CartLine` keyed by authoritative `ProductVariant`;
- user-owned `WishlistItem` keyed by authoritative `Product`;
- server revision/timestamps;
- database constraints for active-cart uniqueness, cart-line uniqueness, bounded quantity and wishlist uniqueness.

## Delivered cart behavior

- get/create current active cart;
- add/increment line;
- set quantity;
- remove line;
- clear cart;
- current B03 price/availability projection;
- positive-stock quantity clamp during explicit validation;
- sold-out/unavailable reporting without inventing stock;
- client price-snapshot mismatch reporting without accepting client price authority;
- bounded deterministic authenticated import/merge of browser cart;
- server reproduction of the frozen frontend product/variant/options identity key.

## Delivered wishlist behavior

- list product IDs;
- idempotent add of published Product;
- idempotent delete;
- user isolation through authenticated server ownership.

B01 SessionAuthentication/CSRF remains the browser mutation boundary and all B04 views require authentication.

## Commerce truth boundary

B04 does not persist authoritative line prices and does not create inventory reservations on ordinary cart mutation.

Current price and availability are projected from accepted B03 authority. B05 remains the owner of final checkout repricing, stock validation and reservation.

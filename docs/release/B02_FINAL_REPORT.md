## Authoritative B02 boundary

B02 makes backend catalog identity and presentation metadata authoritative:

- Brand identity and public slug
- Category identity, hierarchy, and public slug
- Product identity, publication state, public slug, dimensions and display metadata
- Product options and option values
- Variant identity and SKU metadata
- Product/variant media metadata and ordering
- B02 badges

The following are deliberately not authoritative in B02:

- price, discounts, tax — B03
- inventory, stock state, reservations, oversell protection — B03
- shipping eligibility — B05
- full-text search/ranking — B08

Frontend fixtures remain preview/test-only. Public B02 responses identify their source as backend, while price/availability compatibility fields remain fail-closed sentinels rather than business truth.

## Implemented domain

### Brand

- UUID primary identity
- unique public slug
- active flag and deterministic sort order

### Category

- UUID primary identity
- unique public slug
- parent hierarchy using `PROTECT`
- database self-parent guard
- recursive model validation preventing hierarchy cycles
- active flag and deterministic sort order

### Product

- UUID primary identity
- unique public slug
- Brand/Category ownership
- lifecycle: `draft`, `published`, `archived`
- published products require `published_at`
- public visibility is fail-closed for future publication, inactive relations, or missing active public media
- shape/material/color and frame dimensions
- explicit public-access index on status/publication/sort path

### Options and variants

- normalized ProductOption and ProductOptionValue
- ProductVariant UUID identity
- single representation for absent SKU: blank string, not dual NULL/blank
- case-insensitive uniqueness for non-empty SKU
- at most one default variant per product
- ProductVariantOption uniqueness and cross-product ownership validation

### Media

- Django `FileField` + Storage abstraction; no production storage vendor lock-in
- deterministic product-scoped upload path
- alt text, width, height, ordering, active state
- optional variant association
- product/variant ownership validation
- uniqueness of product-level and variant-level media positions

### Badges

- `new`, `limited`, `editorial`
- `sale` intentionally excluded because sale truth belongs to B03 pricing authority

## Public API contract

Read-only `/api/v1/` catalog endpoints cover:

- brands
- categories
- products list
- product detail by slug

Product list filtering is deliberately allow-listed to the frozen frontend needs:

- `brand`
- `category`
- `material`
- `shape`
- `color`

Ordering is deliberately bounded:

- default deterministic order
- `name-asc`
- `name-desc`

Pagination:

- default page size 24
- maximum page size 48

Serializer-related querysets explicitly use `select_related` / `prefetch_related`; query-count regression coverage was added so relational serialization does not silently become N+1 behavior.

## Migration discipline

Permanent migration:

`apps/catalog/migrations/0001_initial.py`

It was generated by Django 5.2.17, not hand-written.

A first candidate exposed an undesirable dual `NULL` / empty-string SKU representation. That candidate was rejected before acceptance. The model was corrected to `CharField(blank=True, default="")`; the stale migration was deleted and a clean initial migration was regenerated by Django.

Temporary write-enabled migration-generator workflows were used only to generate/normalize deterministic migration artifacts and were removed immediately afterward. The accepted implementation tree contains only the permanent read-only Backend Quality Gate.

## Defects found and resolved before closure

1. Ruff format found two formatting deviations in catalog models; corrected without semantic weakening.
2. Ruff Django rules rejected method ordering and `null=True` on the string SKU field; method ordering was corrected and SKU representation simplified.
3. Strict mypy found nullable `ProductMedia.variant` was not narrowed before dereference. The code now explicitly narrows the relation before ownership validation; strictness was not disabled.
4. The first generated migration was discarded and regenerated after the SKU schema correction so no compensating `0002` exists for an unaccepted initial schema.

## Security and integrity notes

Relational invariants expressible in the database are enforced with PostgreSQL/Django constraints. Cross-table ownership invariants that cannot honestly be represented by a simple CHECK constraint are model-validated and covered by tests rather than being misrepresented as database-enforced.

Public catalog visibility fails closed. Draft, archived, future-dated, inactive-relation, and no-active-media products are not public catalog truth.

B02 does not claim payment, price, stock, shipping, or search authority.
